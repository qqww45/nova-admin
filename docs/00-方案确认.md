# DDD Architecture Requirements

## 1. 后端分层实现规范

### A. 领域层 (Domain Layer) - 核心业务逻辑
- &zwnj;**实体 (Entity)**&zwnj;: `User` (聚合根), `Session` (值对象/实体).
- &zwnj;**值对象 (Value Object)**&zwnj;: `DeviceFingerprint` (封装设备指纹逻辑), `TokenPair` (封装 AccessToken 和 RefreshToken).
- &zwnj;**领域服务 (Domain Service)**&zwnj;: `AuthenticationDomainService`.
  - 负责核心校验逻辑：验证密码、检查设备信任状态、生成 Token 对。
  - &zwnj;**注意**&zwnj;：领域层不依赖 Spring 组件，不直接操作数据库或 Redis，只定义接口和行为规则。
- &zwnj;**仓储接口 (Repository Interface)**&zwnj;: `UserRepository`, `SessionRepository` (定义在 Domain 层，实现在 Infrastructure 层)。

### B. 应用层 (Application Layer) - 用例编排
- &zwnj;**应用服务 (Application Service)**&zwnj;: `AuthAppService`.
  - 暴露用例方法：`login(LoginCommand)`, `refreshToken(RefreshCommand)`, `logout(LogoutCommand)`.
  - 负责事务控制、权限校验前置、调用领域服务、调用仓储持久化数据。
  - 输入输出使用 DTO/Command/Query 对象，不与 Domain Entity 直接耦合到外部。

### C. 基础设施层 (Infrastructure Layer) - 技术实现
- &zwnj;**仓储实现 (Repository Impl)**&zwnj;: `MyBatisUserRepository`, `RedisSessionRepository`.
  - 实现 Domain 层定义的 Repository 接口。
  - 处理具体的 DB 查询和 Redis 缓存操作。
- &zwnj;**JWT 工具适配**&zwnj;: `JwtTokenProvider` (实现 Domain 层定义的 TokenGenerator 接口)。
  - 使用 jjwt 0.12.x 生成和解析 Token。
  - 将 DeviceFingerprint 绑定到 Refresh Token 中。

### D. 接口层 (Interface/API Layer) - 对外暴露
- &zwnj;**Controller**&zwnj;: `AuthController`.
  - 接收 HTTP 请求，参数校验 (@Valid)。
  - 调用 Application Service，返回统一响应结果。
  - &zwnj;**注意**&zwnj;：Controller 极其轻薄，不包含任何业务逻辑。

## 2. 关键业务逻辑细节

### 双 Token 与可信设备流程
1. &zwnj;**登录 (`login`)**&zwnj;:
   - AppService 接收账号密码和设备指纹。
   - 调用 DomainService 验证身份。
   - 若设备指纹在 Redis 中存在且有效 -> 视为可信设备，跳过验证码。
   - 若不可信 -> 返回特定状态码，前端触发二次校验。
   - 校验通过后，DomainService 生成 TokenPair。
   - Infrastructure 层将 RefreshToken 存入 Redis (Key: `refresh:{userId}:{deviceId}`)，设置过期时间。
2. &zwnj;**刷新 (`refresh`)**&zwnj;:
   - AppService 接收 RefreshToken。
   - Infrastructure 层从 Redis 获取并校验 RefreshToken 有效性及设备指纹匹配。
   - 校验通过 -> 轮换生成新的 TokenPair，更新 Redis。
   - 校验失败 -> 抛出异常，前端强制登出。

## 3. 前端实现 (保持简洁高效)
- &zwnj;**Axios 拦截器**&zwnj;: 实现请求队列暂停与重试机制，确保 Access Token 过期时静默刷新。
- &zwnj;**Pinia Store**&zwnj;: 管理用户状态，提供 `login`, `refresh`, `logout` 动作。
- &zwnj;**Login View**&zwnj;: 根据后端返回的状态码，动态切换“账号密码登录”与“二次校验”界面。
