# 系统日志方案设计

## 1. 当前设计

### 1.1 输出

`logback` 同时输出到两处：

```
应用 ──► Console Appender（控制台）
     └─► File Appender ──► ./logs/admin-backend.log
```

- 路径由 `logging.file.name` 配置（默认 `./logs/admin-backend.log`，可用 `LOG_FILE` 环境变量覆盖）；
- 开发/生产都会写文件（之前只有 prod 写，导致开发环境下在线查看功能无文件可读）。

### 1.2 在线查看

`GET /system/log/tail?lines=200&level=ERROR&keyword=xxx`（权限 `system:log:list`，仅超级管理员）

设计取舍：

| 决策 | 理由 |
|---|---|
| 返回**原始日志行**，不做结构化解析 | 日志格式由 logback pattern 决定，强行解析会在调整 pattern 时静默失效；原文最稳，也便于复制排障 |
| 只保留最近 N 行的**循环队列**，不 `readAllLines` | 日志可能达数百 MB，一次性读进内存会拖垮应用；循环队列让内存占用恒定 |
| 行数上限 1000 | 防止一次拉取过大响应 |
| **不接受调用方传路径**，只读配置指定的文件 | 防目录遍历（否则 `/system/log/tail?path=../../etc/passwd` 就是任意文件读取） |
| 仅授予超级管理员 | 日志含 IP、UA 等个人信息 |

## 2. 若接入分布式日志系统，是否存在冲突？

### 结论：**不冲突，两者是互补关系，可以并存。**

### 2.1 为什么不会冲突

分布式日志（ELK / Loki / 云厂商日志服务）的采集端（Filebeat、Vector、Promtail）是**只读消费者**：

```
                    ┌─► Filebeat ──► Elasticsearch / Loki ──► 统一查询、告警
应用 ──► 日志文件 ───┤
                    └─► /system/log/tail ──► 单机临时查看
```

- 采集端只读文件，不修改、不删除、不占用写锁；
- 在线查看也是只读，两者读同一份数据；
- 任何一方都不需要对方配合，也不改变对方的写行为。

### 2.2 两者的定位差异（为什么不能互相替代）

| | 在线查看（本机） | 分布式日志系统 |
|---|---|---|
| 覆盖范围 | 单台机器 | 全部实例聚合 |
| 适用 | 单机调试、紧急排障、无外部依赖 | 多实例检索、长期留存、告警、审计 |
| 依赖 | 无 | 需要 ES/Loki + 采集端 |
| 查询能力 | 尾部 N 行 + 简单过滤 | 全文检索、聚合、时间范围、可视化 |

**多实例部署时，在线查看只能看到"负载均衡把你分到的那台机器"**——这是它无法替代集中式日志的根本原因。

### 2.3 需要留意的三个技术点（不是冲突，但会影响稳定性）

| 点 | 风险 | 处理 |
|---|---|---|
| **文件轮转** | logback 按日/按大小切割后，采集端若按文件名跟踪会漏采或重复采 | 采集端用 **inode + offset** 跟踪（Filebeat 默认行为），不要用文件名 |
| **日志格式** | 默认 pattern 是纯文本，结构化查询需要正则提取 | 建议接入 `logstash-logback-encoder` 输出 JSON（`logback-spring.xml` 中切换 encoder），两边都能受益 |
| **时区** | 本机日志用 GMT+8，ES/Loki 常按 UTC 存储 | 统一在采集端打 `@timestamp`（UTC），展示层做转换；不要依赖本地时区字符串 |

### 2.4 建议的接入姿势

1. **保留本地文件**：它是采集端的数据源，也是集中式日志不可用时的最后手段；
2. **日志改为 JSON 输出**（可选但推荐）：一份数据同时满足"人读"和"机读"；
3. **采集端 tail 同一文件**，配置示例（Filebeat）：

```yaml
filebeat.inputs:
  - type: filestream
    paths:
      - /app/logs/admin-backend.log*
    # filestream 按 inode 跟踪，天然兼容轮转
    fields:
      app: admin-backend
      env: ${ENV}
output.elasticsearch:
  hosts: ['http://es:9200']
  index: 'admin-backend-%{+yyyy.MM.dd}'
```

4. **在线查看保留**：它不依赖任何外部组件，在"集中式日志挂了/还没配"的时候最有用。

---

## 3. 一句话总结

在线日志查看与分布式日志系统**不冲突**：前者是单机兜底入口，后者是全局查询能力，共享同一份文件输出。
接入时唯一要动的是把采集端配好（按 inode 跟踪 + 统一时间戳），在线查看功能无需任何改动。
