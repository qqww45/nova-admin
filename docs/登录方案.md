# Goal

核心目标：
1. &zwnj;**日常无感**&zwnj;：99% 的场景下，用户无需输入验证码，Access Token 过期后自动静默刷新，不打断用户操作。
2. &zwnj;**风险可控**&zwnj;：仅在陌生设备/异地 IP 首次登录时触发二次校验（如邮箱验证码或简单的图形验证）。
3. &zwnj;**安全合规**&zwnj;：防止 JWT 泄露后的无限期滥用，支持服务端主动踢人。

# Requirements & Constraints

## 1. 后端实现 (Spring Boot 3 + Spring Security + jjwt)
- &zwnj;**双 Token 机制**&zwnj;：
  - `Access Token`: 短效（建议 15-30 分钟），用于业务接口鉴权。
  - `Refresh Token`: 长效（建议 7-30 天），存储在 Redis 中，Key 为 `refresh_token:{userId}:{deviceId}`，Value 为 Token 字符串。
- &zwnj;**可信设备逻辑**&zwnj;：
  - 定义一个 `DeviceTrustService`，根据 `User-Agent` + `IP段` + `浏览器指纹哈希` 生成 `deviceId`。
  - 登录时检查 Redis 中是否存在该 `deviceId` 的信任记录。若存在，跳过验证码；若不存在，标记为“待验证”，返回特定错误码要求二次校验。
  - 二次校验通过后，将 `deviceId` 写入 Redis 信任列表（设置过期时间）。
- &zwnj;**刷新接口 (`/auth/refresh`)**&zwnj;：
  - 接收 Refresh Token，校验 Redis 中是否存在且未过期。
  - 校验通过后，颁发新的 Access Token 和新的 Refresh Token（轮换机制，可选）。
  - 若 Refresh Token 无效或已被撤销，返回 401，前端强制跳转登录页。
- &zwnj;**安全细节**&zwnj;：
  - 登录失败统一返回“用户名或密码错误”，防止账户枚举。
  - 使用 `jjwt 0.12.x` 的最新 API，确保密钥长度符合 HS256/HS512 要求。

## 2. 前端实现 (Vue 3 + TS + Pinia + Axios)
- &zwnj;**Axios 拦截器**&zwnj;：
  - &zwnj;**请求拦截**&zwnj;：自动携带 Access Token。
  - &zwnj;**响应拦截**&zwnj;：捕获 401 错误。
    - 如果是 Access Token 过期，立即暂停当前请求队列。
    - 调用 `/auth/refresh` 接口刷新 Token。
    - 刷新成功后，重试原请求队列；刷新失败，清除本地存储，跳转登录页。
    - &zwnj;**关键点**&zwnj;：确保刷新过程中用户界面无感知（不弹窗、不跳转）。
- &zwnj;**登录页逻辑 (`Login.vue`)**&zwnj;：
  - 集成 Element Plus 表单。
  - 增加“记住我/信任此设备”勾选框（默认勾选）。
  - 若后端返回“需要二次校验”状态码，动态显示验证码输入框或切换为扫码/邮箱验证模式。
  - 使用 `localStorage` 加密存储 Refresh Token（或使用 HttpOnly Cookie，请给出最佳实践建议）。
- &zwnj;**状态管理 (Pinia)**&zwnj;：
  - `useUserStore`：管理 userInfo, accessToken, refreshToken, deviceId。
  - 提供 `login()`, `logout()`, `refreshToken()` 方法。

## 2. 关键设计决策

| 决策 | 理由 |
|---|---|
| 验证码**默认不渲染** | 99% 场景是已信任设备，不该每次都让用户输验证码；由服务端 1013 驱动 UI 展开 |
| 先不带验证码提交，被拒再补 | 避免"先猜后验"的交互负担；未传验证码且陌生设备 → 1013（该码不表示账号密码有误，防账号枚举） |
| refresh 令牌**覆盖写** | 同一设备同一时刻只有一个有效令牌，旧令牌被盗也只能用一次（轮换真正生效） |
| deviceId 写入 JWT | 刷新时不依赖前端传参，服务端直接从令牌取设备维度，少一个可篡改输入 |
| 登出**不清** deviceId | 否则每次登出再登录都被当成新设备，"低打扰"失效 |
| 存储用接口隔离 | 当前内存实现（单机），换 Redis 只需新增实现类，业务代码零改动 |

Redis Key 设计（生产实现时直接照搬）：

```
device:trust:{userId}:{deviceId}      → 信任时间，TTL 30 天
refresh_token:{userId}:{deviceId}     → 当前有效 refresh 令牌，TTL = refresh 有效期
```

## 4. 已知边界

- 可信设备与刷新令牌当前为**内存实现**：应用重启后信任记录丢失（表现为"重新验证一次"，属于降级为严格而非降级为不安全）；多实例部署需换 Redis 实现。
- 浏览器指纹依赖 canvas，隐私模式下可能降级（其余特征仍可用，不影响可用性）。
