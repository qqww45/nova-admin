# 附录A：Excel 模板定义与字段映射

> 与主提示词配套使用。用于约束"文档模式"的导入导出行为，是从 xlsx 平滑过渡的关键配置。
> 映射关系要求**配置化**（如 `import_mapping` 配置表或 JSON 配置文件），不要写死在代码里。

---

## A.1 通用导入规则

1. 解析：支持 `.xlsx / .xls`；读取第一个工作表（可在上传后让用户选择工作表）。
2. 表头识别：支持**中英文别名 + 模糊匹配**（去空格、去换行、全半角统一、忽略括号内容）。
3. 首行非空单元格数 < 2 的行视为空行，跳过；完全空白行不报错。
4. 校验分两级：
   - **阻断级**（缺必填、数值非法、唯一键冲突且策略为拒绝）→ 该行不入库，进错误清单。
   - **警告级**（建议字段缺失、未匹配到订单明细）→ 入库并标记"待补全"，进《异常数据池》。
5. 幂等策略（每个模块可配置）：`跳过 / 覆盖更新 / 追加`，默认 **跳过** 并计入报告。
6. 错误清单：导出 xlsx，包含「原始行号 + 原行数据 + 错误列 + 错误原因」，修正后可原文件重传。
7. 大文件：行数较多时（阈值由你按现有框架能力自行设定）改为异步任务 + 进度提示。

## A.4 出货导入模板（列序与现有台账保持一致）

| 列序 | 表头 | 系统字段 | 必填 | 规则 |
|---|---|---|---|---|
| 1 | 出货日期 | ship_date | Y | 默认今天 |
| 2 | 加工单号 | process_order_no | N | 幂等键组成部分 |
| 3 | 业务 | salesman_name | Y | 按姓名匹配 |
| 4 | 客户 | customer_name | Y | 按名称匹配 |
| 5 | 客户订单号 | customer_order_no | N | 用于匹配订单 |
| 6 | 客户物料号 | customer_material_no | N | 匹配明细的优先键 |
| 7 | 型号 | model | Y | |
| 8 | 出货数量 | qty | Y | >0 且 ≤ 未出货数 |
| 9 | 料号 | material_no | N | |
| 10 | 规格型号 | spec | N | |
| 11 | 备注 | remark | N | |

**明细匹配优先级**：`客户订单号 + 客户物料号` → `客户订单号 + 型号` → `客户 + 料号` → 未匹配（警告级，入库为"无源出货"并进异常池，允许后续手工挂接）。

## A.5 传统台账导出格式

导出需提供两种模板，由用户选择：

- **系统模板**：字段完整、命名规范，适合系统间交换。
- **传统台账模板**：列序、表头名称、日期格式与原 xlsx **逐列一致**（见 A.3 / A.4 表头），可直接替代原文件发给客户或财务。

导出范围：当前筛选结果 / 勾选行 / 全部。文件名格式建议：`{模块}_{日期范围}_{导出时间}.xlsx`。

## A.6 历史数据体检报告（首次导入后生成）

检查项：
- 客户名称重复或近似（去空格/全半角后比对）
- 订单号重复、订单号相同但客户/日期不一致
- 明细缺料号、缺型号
- 数量 ≤ 0 或含非数字字符
- 税率非字典值
- 单价缺失或异常（0 或极端值）
- 出货数量超过下单数量
- 日期解析失败或超出合理区间

输出为可下载的 xlsx 报告 + 页面内可跳转修复。

## A.7 待确认清单（请填写后投喂）

| # | 事项 | 选项 / 建议默认 |
|---|---|---|
| 1 | 物料编号与料号是否同一编码体系 | 建议：同一字段，表头别名 |
| 2 | 型号 与 规格型号是否需分开 | 建议：分开 |
| 3 | 是否允许超额出货 / 容差比例 | 建议：禁止；如允许需审批 |
| 4 | 加工单号是否全局唯一（能否单独做幂等键） | 建议：否，组合键 |
| 5 | 税率候选值与默认税率 | 建议：0/1%/3%/6%/9%/13%，默认 13% |
| 6 | 是否多币种 | 建议：暂仅 CNY |
| 7 | 已对账明细是否禁止出货 / 改价 | 建议：禁止改价，出货仅警告 |
| 8 | 出货是否需要记录金额 | 建议：记录快照，便于对账 |
| 9 | 客户编号是否需要 | 建议：暂不需要 |
| 10 | 作废 / 回滚 / 删除是否需要审批流 | 建议：二次确认 + 填原因，不上审批流 |
| 11 | 数量是否允许小数及精度 | 建议：允许，4 位小数 |
