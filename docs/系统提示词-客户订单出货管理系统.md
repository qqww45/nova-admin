## 1. 角色与目标

你是本项目的前端+后端全栈开发助手，负责在**现有基础框架**上实现一套"客户—订单—出货"业务系统，用于替代当前以 Excel（xlsx）台账为主的手工管理方式。

核心目标：
1. 功能正确、口径统一（尤其是数量、含税/不含税金额）。
2. **平滑过渡**：系统在很长一段时间内必须与 xlsx 台账共存，使用者可以从"Excel 习惯"零成本切换到系统。
3. 高频操作（订单出货）必须做到"秒级录入"，不能比 Excel 慢。

第一原则：**任何功能都必须同时提供「传统操作模式（界面）」和「文档模式（Excel 导入/导出/粘贴）」，两种模式共用同一套校验与业务规则。**

## 4. 核心业务规则（必须实现，且必须写单元测试）

### 4.1 数量规则
- `qty_open = qty_ordered − qty_shipped`，页面与导出均实时计算，**永不落库为可编辑项**。
- 新增出货：`0 < qty ≤ 对应明细 qty_open`；超额出货需开关控制，默认**禁止**（`[待确认]` 是否允许容差，如允许需审批）。
- 出货保存成功后**回写** `sales_order_item.qty_shipped += qty`（同一事务）。
- **禁止物理删除**出货记录，只允许"作废/红冲"：作废时 `status=已作废` 且回写扣减 `qty_shipped`，保留完整痕迹。
- 订单头禁止删除已有出货的明细行；只能取消（取消前须先作废其下出货）。

### 4.2 税额与单价规则（重点）
- `tax_rate` 为空 或 `= 0` → `unit_price` 视为**不含税单价**：
  - `amount_ex_tax = unit_price × qty`
  - `tax_amount = 0`
  - `amount_tax_included = amount_ex_tax`
- `tax_rate > 0` → `unit_price` 视为**含税单价**：
  - `amount_tax_included = unit_price × qty`
  - `amount_ex_tax = amount_tax_included ÷ (1 + tax_rate)`
  - `tax_amount = amount_tax_included − amount_ex_tax`
- 舍入：金额四舍五入保留 2 位；**税额用"价税合计 − 不含税金额"倒挤**，保证三项恒等式成立。
- 界面与导出必须显式展示"含税/不含税"标签，并在单价列用列头标注，避免误解。
- 税率禁止硬编码，从字典读取；默认候选 0 / 0.01 / 0.03 / 0.06 / 0.09 / 0.13（`[待确认]`）。

### 4.3 订单状态自动流转
| 状态 | 触发 |
|---|---|
| 草稿 | 新建未确认 |
| 已确认 | 手工确认 |
| 部分出货 | 存在明细 `0 < qty_shipped < qty_ordered` |
| 已完成 | 所有有效明细 `qty_open = 0` |
| 已取消 | 手工取消（须先作废出货） |

状态由服务端在出货/作废后重算，禁止前端直接改状态字段。

### 4.4 对账
- 对账日期在**明细级**填写；填写后 `reconcile_status=已对账`。
- `[待确认]` 已对账的明细是否禁止新增出货 / 修改单价（建议：禁止改价，出货仍允许但弹警告）。

### 4.5 默认值与默认项
- 联系人、开票信息在订单/出货选客户后自动带出默认值，允许临时切换。
- 出货录入选择客户订单号后，自动带出客户、型号、料号、规格、未出货数。

## 5. 双模式设计（本系统的关键，务必做到）

### 5.1 传统操作模式（界面模式）
必须提供"像 Excel 一样"的录入体验：
- **可编辑表格**：单元格直接编辑，`Enter` 下移、`Tab` 右移、`Ctrl+D` 向下填充、`Ctrl+C/V` 复制粘贴单元格。
- 行内新增、批量勾选删除、拖拽调整行序（可选）。
- 常用筛选组合可"保存为视图"（如：我的未出货明细、本月待出货）。
- 键盘优先：出货页面支持全键盘完成一笔录入。
- 所有界面录入走**同一套服务端校验**，禁止前端独有规则。

### 5.2 文档模式（Excel 模式）
- **模板下载**：每个模块提供 xlsx 模板，含 ①数据页（表头+1 行示例）②字段说明页 ③字典页（下拉可选值）。
- **导入三步法**：上传 → **预览校验**（表格内展示解析结果，错误单元格标红并显示原因，可下载《错误清单 xlsx》）→ **确认导入**（返回报告：新增 X 条 / 更新 Y 条 / 跳过 Z 条 / 失败 W 条）。
  - 幂等：按 3.x 定义的唯一键做 upsert 或跳过，重复导入不产生重复数据。
  - 支持"仅校验不导入"。
- **剪贴板粘贴**：在列表/明细表格内 `Ctrl+V` 直接粘贴 Excel 区域，按列顺序映射，即时校验并高亮错误行——这是过渡期最高频入口，必须做。
- **导出**：支持 ①导出当前筛选结果 ②导出勾选行 ③**导出为传统台账格式**（列顺序、表头名称与原 xlsx 保持一致，可直接发给客户/财务）。
- **导入批次管理**：可查看历史批次、下载错误清单、**一键回滚**某批次（仅限该批次的增量）。

### 5.3 一致性红线
文档模式与界面模式**共用同一 API 与同一规则引擎**。禁止"导入走宽松校验、界面走严格校验"。

## 7. 从 xlsx 平滑过渡的策略（必须体现在产品设计里）

**阶段 0｜影子期**：导入历史 xlsx，系统只读/可查；使用者继续用 Excel，系统用于查询与核对。产出《历史数据体检报告》（重复客户、缺料号、数量异常、税率异常）。
**阶段 1｜双轨期**：系统录入 + 每日一键导出"传统台账 xlsx"（列序与原表一致），Excel 作为备份习惯保留；导入支持增量。
**阶段 2｜切换期**：系统为准，xlsx 仅用于对外导出与财务归档；保留导入通道应对补录。

配套要求：
- **字段映射配置化**：历史列名 → 系统字段的映射放配置（见附录A），支持别名、默认值、单位转换、缺省容忍，不要写死在代码里。
- **脏数据不阻塞**：允许"待补全"状态入库，集中到《异常数据池》页面逐条修复，而不是导入直接失败。

## 8. 接口约定（REST，前缀 `/api`）

- 客户：`GET/POST/PUT/DELETE /customers`、`/customers/{id}/contacts`、`/customers/{id}/contacts/{cid}/set-default`、`/customers/{id}/invoices`（同构）

- 导出：`POST /export/{type}`（支持 ids / 筛选条件 / 模板类型 = 系统模板|传统台账）
- 字典：`GET /dicts/{code}`

统一响应结构沿用现有基础框架约定。批量接口必须返回**逐行成功/失败明细**。
